# Universal smart short-link system (/link/<code>) with product-page Share button

Adds a universal short-link subsystem to 4A Store v2: a `short_links` table (created via the repo's no-migrate idempotent-SQL pattern plus a Prisma model and a manual `prisma/short-links.sql`), a base62 code service, auto-creation on single + bulk product create, admin CRUD for arbitrary URLs, a public on-demand resolver, and the `GET /api/link/:code` redirect route. The redirect route serves OG preview HTML to social crawlers by reusing `services/ogShare.ts` (no forked OG logic) and a smart-redirect page to humans (Android app via `intent://` to `com.store4a.app` with a ~1.2s Play Store fallback, website otherwise, with `<noscript>`/`<meta refresh>`). Apache reaches Node for both crawlers and humans via one all-UA rule in `deploy/4astore-og.conf`. The frontend adds an admin Links page and a bilingual Share button on the product page.

Watch for: the Android `intent://` fallback timer races against the app-open and uses pagehide/visibilitychange to cancel — behavior differs across Android browsers (likely). The crawler branch falls through to the human smart-redirect page when no OG card is available, which is correct but means a crawler can receive the JS redirect page for custom links (confirmed). Admin link creation accepts arbitrary target URLs including external `http(s)` origins with no allowlist (confirmed) — an open-redirect surface worth a conscious decision.

**Verdict**: APPROVED

## High-level view

The design reuses the existing deploy-safe OG mechanism rather than inventing a parallel one. The one new Apache rule proxies `/link/<code>` to `GET /api/link/:code` for every user-agent (unlike the crawler-gated OG rules), and the Node route does the UA branching. The crawler branch calls `buildProductShareHtml`/`buildPageShareHtml`/`buildCategoryShareHtml` directly, so there is exactly one OG source of truth.

The table follows the repo's no-migrate convention precisely: idempotent `CREATE TABLE IF NOT EXISTS` in `ensureShortLinkTables()` wired at startup beside the other `ensure*` calls, a matching `ShortLink` Prisma model with `@@map`, and a manual `prisma/short-links.sql`. The Prisma client in this worktree was regenerated to include the `shortLink` delegate; the merge target must run `prisma generate` (deploy.sh already does) or the build breaks there.

Auto-create is best-effort everywhere: fire-and-forget on single create, swallow-and-continue in the bulk loop, and the product helper never throws so a link failure can never block a product save. The custom-link helper does throw (surfaced as 409/422 by the admin route) because an admin needs real feedback.

The API surface is small: public `GET /api/products/:id/short-link` (mints on demand), admin `GET`/`POST /api/admin/links` gated on `requireStaff('ads')` and mounted before the generic `/api/admin` router, and the public `GET /api/link/:code`. Admin link creation accepts any URL with no origin allowlist, which is an intentional "any url" requirement but also an open-redirect surface.

The human smart-redirect page attempts the Android app and falls back to the Play Store on a timer; the timer-cancel heuristic is inherently browser-dependent. On desktop it redirects straight to the site. JS-disabled clients still reach the site via `<meta refresh>`/`<noscript>`.

### Transport to Node via one all-UA Apache rule

The OG rules in `deploy/4astore-og.conf` are crawler-UA-gated so humans fall through to the SPA. `/link` can't work that way — humans need the smart-redirect page too — so the new rule is deliberately ungated:

```
RewriteRule ^/?link/([A-Za-z0-9]+)/?$ http://127.0.0.1:4000/api/link/$1 [P,L]
```

It sits first inside the `<IfModule mod_rewrite.c>` block with `[P,L]`, so it proxies and stops before the crawler rules are considered. The code comment ties it to the `app.use('/api/link', …)` mount — the two must move together. deploy.sh step 5b installs this file every deploy, so no deploy.sh change was needed.

### Crawler vs human branching reuses the one OG source

`GET /api/link/:code` branches on `isCrawler(req.get('user-agent'))`. For a crawler it calls `buildProductShareHtml` (or the page/category builder by `type`) from `services/ogShare.ts` — the same builders `/api/og-crawl` uses, so OG logic is not duplicated. On `notFound` or a non-entity type it falls through to the human page.

That fall-through has one consequence: a crawler hitting a `custom`-type link (no product/page/category) receives the JS smart-redirect HTML instead of an OG card. Product links always get the card; custom links won't produce a rich unfurl — worth noting since the admin UI invites arbitrary URLs.

`Vary: User-Agent` is set on every response (and asserted at the Apache edge), so a cached crawler copy can't be served to a human.

### Smart-redirect page and the Android fallback race

```
┌─ Android + intent available ─┐      ┌─ desktop / other ─┐
│ setTimeout(1200ms) → Play     │      │ location.replace   │
│ location.href = intent://…    │      │   (target)         │
│ pagehide/visibilitychange     │      └────────────────────┘
│   → clearTimeout (app opened) │
└───────────────────────────────┘
```

The page arms a 1200ms timer to `location.replace(PLAY_STORE_URL)` and clears it on pagehide/visibilitychange when the app opens. Reliability varies by Android browser — some fire `visibilitychange` on the intent chooser, some don't; on a slow device the 1200ms can fire before the app foregrounds, bouncing an app-having user to the Play Store (or the reverse). Inherent to the technique, not a code defect, but it warrants real-device verification post-deploy.

Interpolation is encoded correctly for each context: `escapeHtml` (escapes quotes) for the `<meta refresh>` and anchor attributes, `JSON.stringify` for the three JS values. A bad/expired code returns a friendly 404 HTML page rather than JSON.

### Auto-create never blocks a save; custom-create reports failure

`createShortLinkForProduct` catches everything and returns `null`, so both call sites are safe: single create in `routes/admin.ts` fire-and-forgets (mirroring `runProductSeo`), and bulk `importProducts()` `.catch(()=>undefined)` per row so one bad link never aborts an import. `createCustomShortLink` deliberately throws instead (`ShortCodeTakenError` → 409, other validation → 422) because the admin route needs to surface the error. That silent-vs-loud asymmetry is the right split.

### API surface and open-redirect consideration

Public `GET /api/products/:id/short-link` mints on demand and returns `{ code }` (`null` only on genuine failure); it's distinct from `/products/:id` by segment count, so no route-shadowing. Admin `GET`/`POST /api/admin/links` are gated `requireAuth, requireStaff('ads')` and mounted before the generic `/api/admin` router.

`POST /api/admin/links` validates `targetUrl` only as a 1–1000 char string and `normaliseTarget` accepts any `http(s)://` URL as-is. That satisfies the "create a link for ANY url" requirement, but it also means an `ads` staffer can mint a short link that redirects to an arbitrary external origin — an open-redirect vector off `4astore.com/link/*`. Blast radius is limited to trusted staff, but it's worth a conscious decision on constraining targets to the site origin or an allowlist.

### Table creation three ways, consistent columns

`ensureShortLinkTables()`, the `ShortLink` model, and `prisma/short-links.sql` declare the same shape and the model carries `@@map("short_links")` + the matching `@@index`. Because the Prisma client isn't committed, the merge target must run `prisma generate` before building — deploy.sh does, but a developer's local main checkout will fail `tsc` (no `prisma.shortLink` delegate) until it does.

### Frontend: admin page and bilingual Share button

The product Share button resolves the short link via `fetchProductShortLink(product.id)` and falls back to the canonical `/product/:id` on null or throw. It uses `navigator.share` when present (swallowing the user-cancel rejection) and otherwise reveals WhatsApp (`waLink`) + Copy fallbacks. `AdminLinks.tsx` surfaces the 409 duplicate-code case via `apiError` + `showToast`; the tab is gated on the same `ads` key as Marketing.

### Verification run

`tsc -p tsconfig.json` in api-node → exit 0, zero errors. `npx prisma validate` with a DATABASE_URL set → "The schema at prisma\schema.prisma is valid". web `npm run build` (generate-sitemap + `tsc -b` + vite) → exit 0; only the pre-existing >500 kB chunk advisory, unrelated to this change. The regenerated worktree Prisma client confirmed to contain the `shortLink` delegate. Live curl/device checks for the crawler OG card, the human redirect, and app-open behavior cannot run in the worktree and remain post-deploy, as the FEAT findings record.
